# CountyIQ data scaffold

This directory defines the intended analytical layer that CountyIQ will eventually consume from the canonical Kenya Data Atlas registries.

## Files

- `roadmap.json` — machine-readable product target state, domain readiness, workstreams, release stages and guardrails.
- `target-schema.json` — target contract for a generated `county-summary.json` analytical mart.
- `county-summary.json` — **not yet committed at scaffold stage**. It should be generated by a future `scripts/countyiq/build-county-summary.mjs` from the Atlas geography, indicator, series, observation, unit and provenance registries.

## Design rule

CountyIQ must not become a second source of truth. The long-term flow is:

```text
Atlas source packages
  -> catalogue/geography/indicator registries
      -> CountyIQ build step
          -> data/countyiq/county-summary.json
              -> CountyIQ website
```

The roadmap may contain `planned`, `sourced`, `research` and `blocked` entries. Those are scaffolding metadata, not statistical observations, and must never be rendered as if they are measured county values.

## Intended generated mart

For each of the 47 counties, the generated mart should expose:

- canonical geography identifiers and boundary version;
- latest eligible metrics plus historical observations;
- period, unit, statistical status and geographic method;
- A-E provenance classification and source drill-through;
- uncertainty metadata where required;
- ranking eligibility, rank, percentile and national benchmark;
- versioned peer benchmark once peer methodology exists;
- matched trend summaries;
- optional indices only after their acceptance gates pass;
- optional development gaps, opportunity matches, documents and recognition only after their own data contracts and validation exist;
- completeness/staleness metadata.

The authoritative target structure is `target-schema.json`.

## Publication discipline

1. Never inherit national WDI values to a county.
2. Never fill missing counties with an average or demo value.
3. Do not rank survey measures when the indicator registry prohibits ranking or required uncertainty metadata is absent.
4. Do not publish the County Development & Performance Index until the composite-index gates in `docs/countyiq/GATES.md` pass.
5. Do not publish a governor score that treats broad county outcomes as personal causation.
6. Do not publish a live opportunity countdown without a verified primary source, status and deadline.
7. Every future recognition must be reproducible from a machine-readable rule.

See `docs/countyiq/PLAN.md` for the full depth tree and `docs/countyiq/GATES.md` for observable acceptance gates.
