# Kenya Data Atlas — Data Completion Roadmap (P18–P26)

This roadmap governs the post-v1.0 programme for resolving every public data slot in the Atlas without weakening provenance, geography or uncertainty rules.

## Completion definition

A public slot is complete only when it has a defensible terminal evidence state. The Atlas must never manufacture a value merely to make a card look complete.

Terminal resolved states will include published direct observations, transparent derivations, appropriately disclosed modelled/external observations, explicit not-applicable states, explicit source-not-published/not-found states, boundary-unresolved states, or a documented retire/replace decision. During the programme, sourced-but-uningested and planned slots remain unresolved.

The canonical machine-readable baseline is generated by:

```bash
npm run completeness:build
npm run completeness:validate
```

Outputs:

- `data/completeness/slot-ledger.json`
- `data/completeness/slot-ledger.csv`
- `data/completeness/summary.json`

For the current public taxonomy the ledger contains exactly **20,115 rendered slot instances**:

- 2,134 county slots, including 66 conditional ASAL resilience slots;
- 3,480 constituency slots;
- 14,500 ward slots;
- 1 national Pulse placeholder slot.

## P18 — Exact completeness ledger and false-empty elimination

**Goal:** make every rendered slot classifiable and remove cases where the UI hides canonical active data because an older placeholder taxonomy wins at runtime.

Outputs:

- deterministic slot-ledger compiler;
- JSON/CSV completeness matrix and summary;
- lifecycle authority fixed so the canonical generated registry wins over stale UI taxonomy status;
- CI validation requiring 20,115 unique slot instances and zero `unknown_missing` rows;
- every unresolved slot mapped to a later completion phase.

Acceptance:

- 20,115 unique slot instances generated;
- county = 2,134, constituency = 3,480, ward = 14,500, national = 1;
- `unknown_missing = 0`;
- a resolved row always has a canonical series and observation;
- an unresolved row always has a reason and completion phase;
- parent values remain prohibited as child-geography fills.

## P19 — Surface existing complete county data

Promote already-ingested 47/47 material into the public county profile rather than leaving stronger canonical data hidden behind generic placeholders. Priority packages: education, connectivity, economic structure and agriculture.

## P20 — Activate straightforward sourced county slots

Ingest and activate source families already identified in the registry: KNBS census, KDHS, Controller of Budget, Auditor-General and transparent facility-density derivations. Preserve survey uncertainty and sensitive-ranking rules.

## P21 — Resolve hard county placeholders

For business licences, exam performance, road length, water access, vehicle registrations, social protection, bed utilisation and similar weak/inconsistent slots: find a primary comparable source or explicitly retire/replace the slot with a stronger governed indicator. No endless permanent placeholders.

## P22 — ASAL resilience completion

Resolve all 66 conditional county resilience slots using NDMA/KMD or a clearly disclosed fallback evidence class where a primary machine-readable channel genuinely does not exist.

## P23 — Constituency completion

Build reusable national ingestion pipelines for constituency population/household measures, registered voters, MP identity, NG-CDF allocation/utilisation, turnout history and facility density. Target: all 3,480 constituency slot instances resolved.

## P24 — Ward completion

Complete MCA identity, turnout history, facility density and other ward slots using canonical ward crosswalks. Ward fund allocation is conditional on an actually published ward-level scheme and must never be produced by mechanically dividing a county budget. Target: all 14,500 ward slot instances resolved.

## P25 — Non-profile surface closure

Resolve National Pulse placeholders and extend the same explicit evidence-state discipline to CountyIQ, Compare, Rankings, Evidence Hub and Opportunity Finder. No public route should contain an unexplained blank.

## P26 — Permanent 100% completeness gate

Promote the ledger to a release-blocking operational control. Target state:

- resolved slots: 20,115 / 20,115;
- unknown blanks: 0;
- canonical active data hidden from the UI: 0;
- parent-to-child inherited values: 0.

The completion dashboard must separately report the share that is numeric/categorical evidence versus explicit source absence, not applicable, boundary unresolved or retired/replaced. A 100% resolved ledger therefore never implies that every cell contains a number.
